# .e 扩展模块二进制布局（本工程生成器）

本文描述 `生成子程序数据` / `生成局部变量数据` / `生成扩展模块数据` 写出的字节结构，
以及 `C:\Users\我的电脑\Desktop\数据\` 下 `head/body/tail/base` 的实测结果。

## 0. 可信度分级

| 级别 | 内容 |
|---|---|
| 已验证（生成器自检） | `scripts/build_e.py --demo --verify`：模块头长度字段、两张标识符表、两处校验和、两个子程序块回读全部通过（1591 字节的示例文件） |
| 已验证 | `base` 前 106 字节（脚本 `scripts/parse_subprogram.py` 跑通，字段全部自洽）；`head/body/tail` 尺寸与记录结构；桌面 11 个非空 `.e` 的魔数与校验和实测结果 |
| 由源码直接推出 | 各字段宽度、拼接顺序、校验和算法、偏移表规则 |
| 未验证 | 生成结果是否被易语言 IDE 接受；`head/body/tail` 是否必须同源（强烈怀疑是） |

## 1. 文件骨架

```
文件 = #head + data + #tail
data = #body + 模块头 + 各子程序块 + 56 字节 0
```

实测尺寸：

| 片段 | 字节数 | 结构 |
|---|---|---|
| `head` | 472 | `CNWTEPRG` + 一组 `19 73` 记录 |
| `body` | 241 | `19 73 11 15` 记录；含 `krnln`、GUID `d09f2340818511d396f6aaf844c7e325`、`系统核心支持库`、`expand` |
| `tail` | 442 | `19 73 11 15` 记录 + 尾部零填充 |
| `base` | 9952 | 完整 `.e` 的一段子程序区（见 §4） |

`19 73` 记录的形状（在三个片段里一致）：

```
19 73 11 15 | 校验和 4B | 19 73 00 NN | NN 字节名称 | NN | 19 73 00 NN × 若干 | 19 73 00 00 00 | ...
```

`head` 的校验和是 `89 CD 06 0A`，`body` 是 `27 F0 8D 3C`，`tail` 是 `DB EB 7D 44`。
**注意**：生成器会在 data 的 4/52/56 偏移覆写这些位置，说明 `#body` 是与生成器配套的模板，
不是随便一个 `.e` 的片段。

## 2. 模块头（`生成扩展模块数据`）

以 `data` 起点为 0：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| 0 | 241 | `#body` |
| 241 | 4 | 子程序数 × 4 |
| 245 | 子程序数×4 | 标识符表，每项 `0x04000000 + 模块编号` |
| … | 8 | 0 |
| … | 4 | 子程序数 × 8 |
| … | 子程序数×4 | 同一批标识符 |
| … | 子程序数×4 | 0（`长度 ÷ 2`） |
| … | — | 各子程序块顺序拼接 |
| 末尾 | 56 | 0 |

拼接完成后做三次回填（位置是 **1 基**，即 `字节集替换` 的第 2 参数）：

| 位置 | 值 |
|---|---|
| 57 | `取字节集长度 (data) - 100` |
| 53 | `GetCheckValue (取字节集右边 (data, 长度))`，长度 = 总长 − 100 |
| 5 | `GetCheckValue (取字节集中间 (data, 9, 92))` |

顺序不能换：53 的校验覆盖 57 已写入的长度字段，5 的校验又覆盖 53 写入的值。

## 3. 子程序块（`生成子程序数据`）

| 偏移 | 宽度 | 内容 | 实测（base 的 `@run`） |
|---|---|---|---|
| 0 | 4 | 版本/标志 `00 00 01 09` | 一致 |
| 4 | 4 | 属性；生成器写 48 | 该片段为 0 |
| 8 | 4 | 返回类型（类型常量） | `0x80000000` 通用型 |
| 12 | 4 | 名称字节数 | 4 |
| 16 | n | 名称（GBK） | `@run` |
| 16+n | 4 | 0 | 0 |
| 20+n | — | 局部变量块 | 见下 |

### 3.1 局部变量块（`生成局部变量数据`）

```
[数量 4][总长 4][标识符 4×数量][偏移 4×数量][变量数据 ...]
总长 = 数量 × 8 + 变量数据长度
偏移[i] = 第 i 个变量数据相对「变量数据」起点的偏移
```

实测：`@run` 数量 3、总长 74 = 3×8 + 50，偏移 0 / 15 / 29，标识符
`0x25010024 / 0x25010025 / 0x25010026`（生成器用 `0x25000000 + 模块编号`，
所以 base 出自另一个版本的生成器，但**布局完全一致**）。

### 3.2 变量数据（`生成变量数据`）

```
[长度 4][类型 4][是否静态 2][数组维数 1][各维尺寸 4×维数][名称][0][备注][0]
长度 = payload 自身长度（不含长度字段）
```

实测 3 个变量：

| # | 名称 | 类型 | 数组 | 长度 | 偏移 |
|---|---|---|---|---|---|
| 1 | `lp` | 整数型 `0x80000301` | 否 | 11 | 0 |
| 2 | `i` | 整数型 | 否 | 10 | 15 |
| 3 | `参数` | 整数型 | 1 维 `[0]` | 17 | 29 |

- 11 = 4(类型) + 2(静态) + 1(维数) + 2(名) + 1(名结束) + 1(备注结束)。
- **类型字段在「变量数据 + 4」**，这就是 `变量序号` 想改的位置。

### 3.3 变量块之后（已用 IDE 存出的模块实测校正）

```
[局部变量表][参数表][偏移表长度 4][偏移表][跳转表长度 4][跳转表 n×9][12 字节 0][代码长度 4][代码]
```

- **参数表**紧跟局部变量表，结构与变量表完全相同；没有参数时就是 8 个 0（老生成器写的
  那「8 字节 0」正是空参数表）。实测 `一参一局`（1 参数 + 1 局部变量）= 局部表 + 参数表两张。
- **跳转表**每项 9 字节：`[块类型 1B][块首偏移 4B][块尾偏移+1 4B]`，按块首偏移升序排列。
  实测块类型：`1` = 如果、`2` = 如果真、`3` = 计次/判断循环。没有块时长度字段为 0，
  表后固定 12 个 0，再跟代码长度。
- **偏移表**：块首记在块的第一字节；块尾（`55 71` 循环尾 / `51 72` 如果结束 / `52 73`
  如果真结束）记在**第二字节**（块首+1），跳转表的「块尾偏移」也用同一个值。
- 只有真实的语句块（长度 > 9）才记偏移；纯跳转标记（`{50}` 否则、`{81,114}`、`{82,115}`、
  `{83,111}`、`{84,116}`）不记。所以**偏移表项数 ≈ 真实语句数**，不是行数。
- 未验证：`判断循环首/尾`（`70` 属性 3 / `55 71` 属性 4）在实测模块里，循环尾**前面还多发
  一个 `6A` 空语句块**，本生成器没有复现；需要用到时先拿 IDE 存的样本对一遍。后来查到原因
  见 §3.4：那个 `6A` 空块正好隔开了「如果结束 紧跟 判断循环尾」。

### 3.4 块尾相邻：IDE 会认错缩进（实测踩坑）

**现象**：`.e` 打开后，某个 `计次循环尾 ()` 显示在循环体缩进里、循环的虚线一直穿到文件末尾，
后面所有语句都多缩进一级。改代码不重排就无法消除。

**触发条件**（两种，都在实测里复现过）：

1. 块尾标记紧贴循环尾：`如果真结束`（`52 73`）后面直接跟 `计次循环尾`（`55 71 …`）；
2. 两个块尾标记相连：`如果结束` 紧跟 `如果结束`（嵌套分支同时结束）。

此时 IDE 把后面的块尾当成前一个块的结束，块没闭合，缩进就错位；**文件本身结构是自洽的**
（回读校验会全部通过），所以只能从写法上规避。

**规避写法**（生成 spec 时就这么写）：

- 循环体最后一条语句要是**普通语句**：结果先算到临时变量，出了块再拼接。

  ```e
  .计次循环首 (取数组成员数 (行), i)
      行文本 ＝ “”
      .如果真 (行 [i] ≠ “”)
          行文本 ＝ 到文本 (i) ＋ “. ” ＋ 行 [i] ＋ #换行符
      .如果真结束
      结果 ＝ 结果 ＋ 行文本      ' ★ 有这句，循环尾就不贴块尾了
  .计次循环尾 ()
  ```

- 嵌套分支同时结束时，用 `选择 (...)` 把分支压成一条语句：

  ```e
  片段 ＝ 选择 (码 < 128, “…”, 选择 (码 < 2048, “…”, “…”))
  ```

- `build_e.py` 生成时会自动检查这两种相邻并在 stderr 打「结构警告」，看到就别交付。

**旁证**：真实模块里 `判断循环尾` 前面那个 `6A` 空语句块，正是 IDE 自己插入的「隔断」。

## 4. base 实测

`parse_subprogram.py` 解析结果：

```
子程序 @run  长度 106 字节（只到变量块结束）
  返回类型 0x80000000 (通用型)
  变量 3 个，总长 74
    lp / i / 参数(1 维 [0])
```

106 字节之后不是生成器的「8 字节 0 + 偏移表」，而是另一套表（可见 21 个
`0x2501000F`–`0x25010023` 标识符、间距约 `0x11` 的偏移表、`子程序地址` 等名称）。
结论：**`base` 是完整 `.e` 的子程序区片段，不是生成器产物**；它的价值是佐证 §3 的布局，
不能直接拼接进生成器输出。源码里被注释掉的 `' count ＝ count ＋ 13` 说明作者曾想把它并进
标识符表，但 `base` 里可见 21 个标识符，到底该并入哪些并没有定论——**不要贸然打开这行**。

## 6. 校验和 `GetCheckValue`

```e
key_len ＝ 4
key ＝ 取空白字节集 (4)
.计次循环首 (取字节集长度 (data), i)
    key [i ％ 4 ＋ 1] ＝ 位异或 (key [i ％ 4 ＋ 1], data [i])
.计次循环尾 ()
返回 (取字节集数据 (key, 3, ))
```

即把数据按 4 字节分组滚动异或，结果按小端读成整数。

**实测警告**：对桌面上的 11 个非空 `.e`（`omg.e`、`找书.e` 等）验证
`b[4:8] == GetCheckValue(b[8:100])` 与 `b[52:56] == GetCheckValue(b[100:])`，
**全部不成立**，`b[56:60]`（长度字段）也全是 0。说明 4/52/56 这组偏移是「本模板族」
的约定，不是 `.e` 通用格式。换 `head/body/tail` 时必须重新确定这三个位置，并实测回读。

## 7. 限制

1. `head/body/tail` 必须来自同一模板（怀疑由同一版本 IDE 导出），混用会破坏 `19 73` 记录链。
2. 生成器写出的块没有在易语言 IDE 里打开验证过；改动后至少用 `scripts/parse_subprogram.py`
   做结构回读，并对比 `base` 的字段宽度。
3. `到字节集 (数值)` 得到定长小端二进制（4 字节整数 / 2 字节短整 / 1 字节字节型），
   `到字节集 (文本)` 得到 GBK 字节。若你的版本行为不同，用 `templates.md` 里的
   `整数到字节集` 兜底。
