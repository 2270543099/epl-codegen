# 已修正的代码模板

以下代码是原工程（`wnxd_macro` 生成器）的修正版，改掉的问题都在注释里标了 `' ★`。
标点风格与原工程一致：字符串 `“”`、运算符全角、分隔符半角。

## 0. 编译单元骨架

```e

写到文件 (取运行目录 () ＋ “\wnxd_macro.e”, 生成扩展模块数据 (子程序数据))
```

- `#head`、`#body`、`#tail` 是**字节集常量**（常量表里存二进制）。
- `#启动子程序`、`#临时子程序` 是**文本常量**，内容就是要编译的子程序源码。
- `#文本型值` 等类型常量见 `epl-syntax.md` 第 7 节。

- 越界检查 `变量序号 ≤ 变量数` 是必须的；原代码完全没有。

## 7. 改完怎么验

**如果目标只是要一个 `.e` 文件，不用在 IDE 里拼**：直接用 `scripts/build_e.py`
（`--spec spec.json --out x.e --verify`），本文件的修正它已经全部实现。

1. 先跑原程序生成 `wnxd_macro.e`。
2. 用 `scripts/parse_subprogram.py` 回读第一个子程序块：

```powershell
python "$env:DSH_HOME\skills\epl-codegen\scripts\parse_subprogram.py" wnxd_macro.e --offset 0 --header-only
```

3. 对照 `base` 的解析结果（`@run`：通用型、3 个变量、变量块总长 74）确认字段宽度一致。
4. 结构通过后，再用易语言 IDE 打开生成的文件，确认子程序列表、变量类型、代码段都正确。
   **结构自洽 ≠ IDE 能打开**，这一步不能省。
5. 生成时如果打出「结构警告」（块尾紧邻循环尾 / 块尾连块尾），先按 `e-binary-layout.md` §3.4
   改写法——这类文件 `--verify` 会全绿，但 IDE 里缩进和块虚线会错位。
